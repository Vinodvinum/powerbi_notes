Power BI Notes

Complete guide to Power BI for Data Analysts — Simple, Practical, Interview-Ready

Phase 1: Foundation — Understanding BI

What is BI & Power BI

🧠 What is Business Intelligence?

BI = Business Intelligence. Meaning: Using data to make better business decisions.

🏢 Real Story (Amazon Analyst)

You work at Amazon. Manager asks: "How are our sales performing?"

You have raw data:

order_id   amount    city
1          5000      Bangalore
2          3000      Mysore

❗ Problem

If you show this table → Manager won't understand quickly. Too much raw data.

💡 Solution = BI

Instead show:

  • Total Sales → ₹8000
  • Top City → Bangalore
  • Trend → Increasing

📊 What is Power BI?

Power BI is a tool used to create reports and dashboards from data.

SQL = get data
Power BI = show data visually

🎯 Example Dashboard

  • 📊 Bar chart → sales by city
  • 📈 Line chart → monthly trend
  • 🔢 Card → total revenue
Answer: BI is converting raw data into meaningful insights. Power BI is the tool that helps create visual dashboards for business decisions.

🎤 Interview Answer

"What is Power BI?"

Power BI is a business intelligence tool used to transform raw data into interactive dashboards and visual reports, helping businesses make data-driven decisions.

🧪 Practice Questions

Q1: Why can't we just use Excel tables?
Ans: Excel is limited to small datasets. Power BI handles larger data, real-time updates, and professional dashboards.
Q2: What is the difference between SQL and Power BI?
Ans: SQL gets data. Power BI visualizes it. Both are needed.

Data Modeling (VERY IMPORTANT)

🔗 Relationships (Like SQL Joins)

Connect tables so Power BI understands relationships.

Star Schema Concept

Fact Table (center): fact_sales
  ├── order_id
  ├── customer_id
  ├── amount
  └── date

Dimension Tables (around):
  ├── dim_customers (customer_id, name, city)
  ├── dim_products (product_id, name, category)
  └── dim_date (date, month, year)

How to Create Relationships

  1. Go to Model View
  2. Drag customer_id from fact_sales to dim_customers
  3. Select relationship type (1-to-many)
  4. Click OK

Fact vs Dimension Tables

Fact Table Dimension Table
Contains measures (amount, quantity) Contains attributes (name, city, category)
Many rows (transactions) Few rows (master data)
Uses foreign keys Uses primary keys
Answer: Star schema: fact table in center, dimensions around it. Relationships connect them like SQL joins.

🧪 Practice

Q1: What is a fact table?
Ans: Table with measurements (amount, count) that connects to dimensions
Q2: How to create relationship?
Ans: Model View → drag foreign key to primary key

Phase 4: DAX — Formulas & Measures

What is DAX

🧮 DAX = Data Analysis Expression

Language for creating calculations in Power BI.

Calculated Column vs Measure

Calculated Column Measure
Computed row-by-row Computed in filter context
Added to table Not in table (only results)
Use rarely Preferred for aggregations

Basic Measure Example

Total Sales = SUM(fact_sales[amount])
Answer: DAX creates measures (preferred) and calculated columns. Measures are evaluated at query time.

Aggregations in DAX

📊 Common Functions

SUM

Total Amount = SUM(fact_sales[amount])

AVERAGE

Avg Order = AVERAGE(fact_sales[amount])

COUNT

Total Orders = COUNT(fact_sales[order_id])

CALCULATE (Context Filter)

Sales Bangalore = CALCULATE(
    [Total Sales],
    dim_customers[city] = "Bangalore"
)
Answer: SUM, AVERAGE, COUNT for basic aggregations. CALCULATE for conditional measures.

🧪 Practice

Q1: How to sum filtered data?
Ans: Use CALCULATE with condition

Time Intelligence

⏰ Time-Based Calculations

YTD (Year-to-Date)

Sales YTD = CALCULATE(
    [Total Sales],
    DATESYTD(dim_date[date])
)

MTD (Month-to-Date)

Sales MTD = CALCULATE(
    [Total Sales],
    DATESMTD(dim_date[date])
)

Previous Month Comparison

Sales Last Month = CALCULATE(
    [Total Sales],
    SAMEPERIODLASTYEAR(dim_date[date])
)
Answer: Use DATESYTD, DATESMTD, SAMEPERIODLASTYEAR for time calculations. Need proper Date table.

🧪 Practice

Q1: How to calculate YTD?
Ans: Use DATESYTD function with CALCULATE

Phase 5: Advanced Analytics

Filters & Context (CRITICAL)

🔍 Row Context vs Filter Context

Row Context

In calculated columns (row-by-row evaluation)

Filter Context

In measures (aggregate based on filters)

How Visuals Work

Slicer filters → Filter context
→ Measures recalculate
→ Visual updates
Answer: Filters change measure results, not data. Understanding context is key to correct formulas.

Drill-through & Interaction

🔗 Cross Filtering

Click on one visual → other visuals filter automatically

Drill-down

Click on bar → see detail (Year → Month → Day)

Drill-through

Click on value → navigate to detail page

Answer: Cross-filtering, drill-down, drill-through enable exploration and detail investigation.

Performance Optimization

⚡ Speed Up Your Dashboard

1. Data Model Optimization

  • Remove unused columns
  • Use appropriate data types (Integer not Text for numbers)
  • Minimize calculated columns (use measures instead)

2. Reduce Data Volume

Filter large tables in Power Query
Example: Only last 2 years of data
Not all historical data

3. Aggregation Tables

Pre-aggregate data for faster queries on large datasets

Answer: Optimize model, reduce data, use measures over columns, aggregate when needed.
