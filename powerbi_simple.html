Chapter 1

What is BI & Power BI

Step 1: What is Business Intelligence?

BI = Business Intelligence. Meaning: Using data to make better business decisions.

Example: Instead of guessing, you use real data to decide which city to focus on.

Real Amazon Story

You work at Amazon. Manager asks: "How are our sales performing?"

You have raw data:

order_id  amount  city
1        5000    Bangalore
2        3000    Mysore
3        4000    Bangalore

Problem: Manager looks at this table and still doesn't understand. Too much raw data.

Solution: Instead show:

  • Total Sales → ₹12,000
  • Top City → Bangalore (₹9,000)
  • Trend → Stable

Now manager instantly understands!

Step 2: What is Power BI?

Power BI is a tool used to transform raw data into visual reports and dashboards.

Raw Data → Power BI → Beautiful Dashboards → Business Decisions

Think of it as: Excel on steroids, but specifically for data visualization.

Step 3: Why Power BI?

  • Speed: Create dashboards in hours, not weeks
  • Power: Handle millions of rows easily
  • Visuals: Charts, graphs, maps, KPIs
  • Interactivity: Click to filter, drill down into data
  • Real-time: Update automatically as new data arrives

Interview Answer

"What is Power BI?"

Power BI is a business intelligence and data visualization tool developed by Microsoft. It transforms raw data into interactive dashboards and visual reports, enabling businesses to analyze data and make data-driven decisions quickly and efficiently.

Practice Questions

Q1: Why can't we just use Excel instead of Power BI?

Ans: Excel works for small datasets. Power BI handles large datasets, real-time updates, and professional interactive dashboards.

Q2: What is the difference between SQL and Power BI?

Ans: SQL gets data from databases. Power BI visualizes that data beautifully. Both are needed.

Q3: Can Power BI replace SQL?

Ans: No. SQL is for retrieving data. Power BI is for showing that data visually.

Chapter 2

Power BI Interface (Very Important)

Step 1: Three main views

Power BI has three workspaces:

View Purpose
Report View Create charts and dashboards (most used)
Data View See and edit your data
Model View Create relationships between tables

Step 2: Report View anatomy

  • Fields Pane (Right): Shows your tables and columns. Drag here to add data to charts.
  • Visualizations Pane (Right): Bar chart, line chart, pie chart, table, etc.
  • Canvas (Center): Where you build your dashboard
  • Filters Pane (Left): Filter your data by conditions

Real workflow

1. Drag "City" from Fields → Canvas

2. Drag "Sales" from Fields → Canvas

3. Power BI automatically creates a chart

4. Choose chart type (Bar, Line, Pie)

5. Done! Interactive chart created.

Interview Answer

Power BI interface has three main areas: Report View (for building dashboards), Fields pane (showing data), Visualizations pane (choosing chart types), and Filters pane (filtering data). The workflow is drag-and-drop: drag data fields onto the canvas, choose a visualization, and Power BI creates the chart automatically.

Practice Questions

Q1: What is the Fields pane?

Ans: It shows all your tables and columns. You drag from here to create charts.

Q2: Which view is for building dashboards?

Ans: Report View.

Q3: Can you see raw data in Power BI?

Ans: Yes, in Data View.

Chapter 3

Data Loading (Get Data)

Step 1: What does Get Data mean?

Get Data = Import data from external sources into Power BI.

Without data, Power BI is empty. This is the first step.

Step 2: Common data sources

  • Excel files: .xlsx files
  • CSV files: Comma-separated text
  • SQL databases: SQL Server, MySQL, PostgreSQL
  • Cloud databases: Azure, Google BigQuery
  • Web APIs: Real-time data from websites
  • Excel workbooks: From SharePoint or OneDrive

Amazon example

Your manager gives you a CSV file with customer data. You do:

1. File → Get Data → CSV
2. Select the file
3. Choose delimiter (comma)
4. Load into Power BI
5. Data is now ready for analysis

Step 3: How to Get Data

In Power BI Desktop:

Home tab → Get Data → Choose source type (Excel, CSV, SQL, etc.)

Interview Answer

Get Data is the process of importing data from various sources (Excel, CSV, databases, APIs) into Power BI. This is the first step in any Power BI project because without data, you cannot create any reports or visualizations.

Practice Questions

Q1: Can Power BI connect to SQL databases?

Ans: Yes, directly via Get Data → SQL Server (or other database type).

Q2: What is the first step of any Power BI project?

Ans: Get Data from a source.

Chapter 4

Power Query Basics

Step 1: What is Power Query?

Power Query = Tool to clean and transform raw data before analysis.

You don't want messy data in your dashboard!

Real scenario

You import a CSV file. Data looks like:

customer_idnamecity
1Vinod Kumarbangalore
2Ravi SinghMYSORE
Asha PatelBangalore

Problems: Inconsistent city names (bangalore vs MYSORE), extra spaces, missing customer_id.

Power Query fixes this: Standardize case, trim spaces, remove blanks.

Step 2: Common Power Query operations

  • Remove duplicates: Delete repeat rows
  • Change data type: Text → Number → Date
  • Filter rows: Keep only what you need
  • Split columns: "Bangalore-Electronics" → Two columns
  • Merge queries: Combine two tables
  • Custom columns: Create new calculated columns

Interview Answer

Power Query is used to extract, clean, and transform data before it's loaded into Power BI. It helps remove duplicates, handle missing values, standardize data formats, and prepare data for analysis and visualization.

Practice Questions

Q1: Why use Power Query instead of cleaning in Excel?

Ans: Power Query is reusable. If source data changes, Power Query automatically re-applies transformations.

Q2: Can Power Query create new columns?

Ans: Yes, using Custom Column feature.

Chapter 5

Data Transformation & Modeling

Step 1: Data transformation

Converting raw data into format suitable for analysis.

Example: Date "2024-01-15" → Extract year, month, quarter for trend analysis.

Step 2: Data modeling

Creating relationships between tables so Power BI understands connections.

Example: Connect Customers table to Orders table using customer_id.

Real scenario

You have:

  • Customers table (customer_id, name, city)
  • Orders table (order_id, customer_id, amount)

Create relationship: Customers.customer_id ← Orders.customer_id

Now Power BI knows: Each customer can have multiple orders.

Interview Answer

Data transformation prepares data for analysis. Data modeling creates relationships ensuring accurate calculations, proper filtering, and trustworthy dashboards.

Practice Questions

Q1: What happens without correct relationships?

Ans: Calculations become wrong, leading to unreliable insights.

Chapter 7

Dashboard Design Excellence

Step 1: Dashboard principles

  • Purpose first: What question does this answer?
  • KPIs at top: Most important metrics first
  • Logical flow: Left to right, top to bottom
  • Consistent colors: Red=bad, Green=good
  • Minimize clutter: Only essential visuals
  • Interactive filters: Let users explore

Real dashboard layout

Top row: Total Sales (KPI), Avg Order Value (KPI), Top City (Card)

Middle: Sales by City (Bar), Category Performance (Pie)

Bottom: Monthly Trend (Line), Top 10 Customers (Table)

Interview Answer

Good dashboards put KPIs at top, arrange visuals logically, use consistent colors, minimize clutter, and provide interactive filters. The goal is telling a clear story, not showing every metric.

Practice Questions

Q1: Where to place most important KPI?

Ans: Top left corner.

Q2: How many visuals should a dashboard have?

Ans: 5-10. Too many causes confusion.

Chapter 8

What is DAX & Aggregations

Step 1: DAX = Data Analysis Expressions

Formula language for Power BI to create complex calculations.

Similar to Excel formulas but more powerful for large datasets.

Step 2: Common aggregation functions

FunctionMeaning
SUM()Add all values
AVERAGE()Calculate average
COUNT()Count numbers
MIN()Lowest value
MAX()Highest value

Real usage

Total Sales = SUM(Orders[Amount])
Avg Order Value = AVERAGE(Orders[Amount])
Customer Count = COUNTA(Customers[ID])

Interview Answer

DAX aggregates large datasets efficiently. Functions like SUM, AVERAGE, COUNT summarize data. DAX handles millions of rows instantly, which Excel can't do.

Practice Questions

Q1: Difference between COUNT and COUNTA?

Ans: COUNT counts numbers only. COUNTA counts any non-blank cell.

Chapter 9

Time Intelligence

Step 1: Time Intelligence functions

  • YTD (Year-to-Date): Sum from Jan 1 to today
  • PREVIOUSYEAR(): Data from same period last year
  • YOY Growth: Compare current year vs previous year

Real example

Manager asks: "How do sales this year compare to last year?"

Current Year = SUM(Orders[Amount])
Previous Year = CALCULATE(SUM(Orders[Amount]), PREVIOUSYEAR(Calendar[Date]))
YOY Growth % = (Current - Previous) / Previous * 100

Interview Answer

Time Intelligence enables year-over-year comparisons and trend analysis, helping identify seasonal patterns and growth trends.

Practice Questions

Q1: How to calculate sales for same period last year?

Ans: Use PREVIOUSYEAR() function.

Chapter 10

Filters, Context & Performance

Step 1: Filter context

Filter context = Which data is visible based on user selections.

When user clicks "Bangalore", only Bangalore data shows.

Step 2: Performance optimization

  • Filter data early in Power Query
  • Use aggregations instead of raw data
  • Optimize DAX formulas
  • Limit visuals per page (5-10)
  • Reduce file size

Interview Answer

Proper filtering and optimization ensure fast dashboards. Filter early, use efficient formulas, limit visuals, and reduce data size.

Practice Questions

Q1: Why filter in Power Query instead of Power BI?

Ans: Reduces file size and improves performance.

Chapter 11-18

Building Dashboards & Storytelling

Complete workflow

  1. Get Data → Import from source
  2. Power Query → Clean and transform
  3. Data Modeling → Create relationships
  4. Visualizations → Build charts
  5. Dashboard → Arrange and filter
  6. Storytelling → Explain insights
  7. Publish → Share with team

Real Sales Dashboard Project

Visuals: KPI cards (sales, orders, customers), bar chart (sales by city), pie chart (category), line chart (trend), table (top customers), slicers (date, city)

Story: "Sales are ₹1M monthly, but Bangalore dropped 30% while Mysore grew 50%. Recommend increasing Bangalore marketing and investigating competition."

Interview questions

Q: Explain your Power BI project.

I created a sales dashboard connecting to order data. Used Power Query to clean data, created relationships between customers and orders, designed visuals showing sales by city/category/time, added interactive filters, and published insights showing which cities need attention.

Q: How would you investigate sales decline?

Create dashboard with sales filtered by: city, category, customer segment, time period. Add drill-through to see details. Look for where decline is happening specifically. Identify root cause and recommend actions.

Q: What's your performance optimization strategy?

Filter data in Power Query (only relevant rows), use aggregations, optimize DAX (avoid complex formulas), limit visuals per page, and reduce file size for fast loading.
